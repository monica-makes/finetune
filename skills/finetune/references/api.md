# finetune API, v0

## finetune(options)

One call makes one panel. It returns nothing.

| option | default | what it does |
| --- | --- | --- |
| `id` | `"finetune"` | Panel title and the localStorage key `finetune:<id>`. Calling again with the same `id` replaces that panel. |
| `key` | `"t"` | Hotkey for **Hide UI** (Figma's Minimize UI): hides the panel, the toolbar, the Design / Motion bar, the grid and the selection at once, leaving only the Hide UI button (at the right of the panel's top row) in a small box where it sat, to bring them back; from fully hidden (`open: false`) it shows everything. Figma's ⌘\ and ⇧⌘\ (Ctrl on Windows) do the same, and the toolbar's tooltip shows the key. Ignored while focus is in an input, textarea, select or contenteditable, and while Cmd, Ctrl or Alt is held. |
| `target` | `":root"` | Selector the CSS variables are written on. Every match gets them. |
| `controls` | `{}` | Key to control. A key starting with `--` is the CSS custom property it writes. Any other key only reaches `onChange`. |
| `presets` | `{}` | Name to values. A preset sets the keys it names and leaves the rest. |
| `onChange` | none | Called with every value: once when the panel mounts, then after each change. |
| `open` | `true` | Whether the inspector and toolbar show on load. `false` starts them hidden, for a page where the hotkey or a button opens them. |

It mounts as soon as the page has a body, so the call can sit in `<head>` or at the end of `<body>`.

`finetune.toggle()` shows or hides the inspector and toolbar together (the hotkey only does Hide UI, keeping the Hide UI button); `finetune.toggle(true)` and `finetune.toggle(false)` set them. Use it for a page's own "open the panel" button, or to hide them when a single-page app leaves the page.

`finetune.reset()` forgets every saved edit and reloads the page as written, the same as the panel's Reset. Just before it reloads, it fires `finetune:reset` on `window`: a page with state of its own (its own controls, its own localStorage) listens for it and resets that too, so one Reset clears everything.

Mark a page's own controls (its nav, its buttons) with `data-finetune-ui`: the inspector never selects them, and they keep working while it's open. Never put it on the content she wants to edit, or nothing in it can be selected.

## The inspector

- **Toolbar** (left), as Figma's left rail: each tool a 40 box with its icon (drawn at the rail's size) and its name 4 under it, Copy and Save, 72 apart and 12 in from the rail's edges (measured off Figma's rail); hover greys the box and nothing stays picked. Copy changes (its tooltip reads "Copy changes and prompt") and Save (its tooltip reads "Save changes in this browser"). **Hide UI** (the hotkey, T by default, or ⌘\ / ⇧⌘\) sits at the right of the panel's top row; hidden, it stays in place as a small box of its own. The top row stays put when the panel scrolls. Popovers and menus have 13px corners (UI3's radius-large); the panel, toolbar and bar have 8px. A panel button stays highlighted (UI3's selected pair: bg-selected behind its icon in icon/selected; UI3's pink pair in Motion) while its menu or popover is open or its toggle is on; an eye stays highlighted while its layer, fill or effect is hidden. The panel's scrollbar floats over its content, as Figma's does (the content keeps its 240 when the panel scrolls): a 4px pill with no track, 2px in from the panel's right edge and 4px from its top and bottom, that drags like a scrollbar, and the panel doesn't bounce at its ends (or scroll the page once it reaches one). They're actions, so none stays pressed. Hovering one shows its name. **Reset to the code's last presets** sits in the panel's top row, after Undo and Redo. **Design** and **Motion** (Figma's Design and Prototype) sit in a bar at the bottom of the window, as Figma's toolbar does, each with its icon and name; the chosen one is filled with the accent, its icon and name white, as Figma's selected tool (blue, pink in Motion). The bar takes finetune's theme, as the rest does (the next bullet); Design shows everything below; Motion is the next bullet. The bar hides with the panel.
- **Theme, colours and icons: Figma UI3's** (the UI3 kit's Colors, effect styles and Icons, 2026-10-14). Every colour is a UI3 colour token, light or dark, named in PANEL LOOK's comments; shadows are UI3's elevation styles (200 the bar, 300 tooltips, 400 popovers, menus and the controls panel); menus, tooltips and toasts stay dark in both themes, as UI3's are. The theme follows the system (`prefers-color-scheme`) until **⌥⌘T** (Ctrl+Alt+T elsewhere) flips it; the flip is kept in this browser (`finetune:theme`), and a flip back to the system's theme goes back to following the system. It's set as `data-ft-theme` on `html`. Two are finetune's own (her calls): the panel's container is pen.dev's (`#F8F8F8` with a `#E3E3E3` border in light; UI3's `#2C2C2C` and `#444444` in dark), and Motion's accent is UI3's pink where Design has its blue. The overlays on the page (selection, hover, marquee, size label, component outline) take UI3's canvas colours, which follow the theme. Icons are the UI3 kit's, 24 frames shown at 1:1 (never scaled; a smaller slot centres one with negative margins), the panel's small variants where Figma's panel uses them. Three aren't in the kit and stay Phosphor's, at 16 inside a 24 frame: Save's floppy disk (her pick) and Undo / Redo's U-turn arrows. Reset is UI3's restart arrow (her pick). Sizes follow UI3's grid (its Spacing page): controls 24 tall in 40px heading rows, list rows 32, corners on UI3's radius tokens (2, 5, 13); the 8px floating boxes, the bar's 6px inset and what was measured off Figma's own panel (the 48px header, the picker's 4px corners, its 12px gaps) stay as they are.
- **Aligning to columns** (Design, while a Horizontal layout shows). A click on empty space inside one of its columns (the page itself under the pointer, not a gutter or margin) picks that column: it's outlined as a selection is, and hovering the page outlines the column a click would pick. Shift-click adds more columns, or layers (or takes one back off). The kind line names them: "Column 3", "Columns 3–5" (in a row) or "Columns 2, 5", "of 12", and the layer count on the right. Just columns: Figma's help card ("Aligning layers to a column", the column grid icon, "Shift-click layers to align them to this column. Add more columns to align across them or match their width."; several: "Aligning layers to columns", the columns icon, "Shift-click layers to align them to these columns or match their width."), no close. Columns and layers: **Position** with **Align to column(s)**: left, center and right line the layers up with one column's edges and middle, or with several columns' leftmost edge, middle and rightmost edge (⌥A ⌥H ⌥D too; a group moves as one), its how-to under it. With two or more columns, **Layout** follows: the layers' **Dimensions** (W and H, Mixed when they differ) and **Match layer width(s) to N columns** (N is the span, the columns between included): each layer takes the span's width and lines up with its left edge (an image or vector keeps its proportions), its how-to under it. Escape, a click elsewhere or switching to Motion lets the columns go, as does hiding or changing the layout so they're gone. While a layout shows and nothing is selected, a card sits at the bottom of the panel with the full how-to and Figma's close; closed, it stays closed in this browser (`finetune:tip:column`). Aligning or matching to columns of a layout that isn't a saved style yet shows a toast for 15 seconds, once a visit per layout: "Save this new column style?" with **Page** and **Website** (Save as style's "Just this page" and "Apply to all pages"; neither is the primary) and a close. The tips say "layers", Figma's word for what's on the canvas.
- **Spacing and type, measured against Figma's own panel (2026-10-14).** The panel's content is 240 wide (the panel 242 with its border): fields 88, 8 apart, the action column 24 at the right, 16 in on the left and 8 on the right. Section titles are 11px/550 in a 40px band; rows start 4 under it; a section ends 16 under its last row. Field labels are 9px on a 14px line, weight 450 (UI3's body/small), in the secondary color; two fields with a label between them sit 24 apart (26 after a row without a label); rows without labels sit 8 apart. The selection's header is 48 tall with its name at 13px/550 on a 22px line, tracked -0.25% (UI3's body/large/strong). Fill and stroke rows end at 172 when they have two buttons (4 apart). The checkbox is 16. Constrain proportions (beside W and H) wears UI3's link icon. The color picker: a 208 square with 4px corners, then two 16px tracks 12 apart beside the eyedropper, then the hex row, each 12 apart; knobs are 16 with a 4px white ring. Menus: items 24 tall, 4 in on the left and 8 on the right, a line between groups with 7 above and below; the blend modes are in Figma's groups. Corner smoothing's slider is a 16px pill with a 16px knob. Motion follows the same rhythm: Playback speed is a section with its name in the 40px title band and the speeds 4 under it; each group of an animation's settings starts 12 under its line and ends 16 under its last row; its side labels are 11px in the secondary color. Independent corners sit two by two in the field columns, Corner smoothing beside the bottom pair.
- **Motion** (Figma's Prototype tab, true to the code). It's for tuning motion the code already has (one she described to Claude Code, say, whose timing or easing doesn't feel right yet), not making it from scratch. It reads CSS animations (`@keyframes`) and JavaScript ones made with `element.animate()`; what it can't read (libraries that animate frame by frame themselves, like GSAP or most of Motion for React, and CSS transitions) is in the README's "Motion: what it can tune". For one layer, or a group of layers that run the same animation (or none yet: a ⌘G group, made this visit or before, acts as one unit): its kind line first, then **Playback speed**, then its **Animation**. Several layers show only their kind line: motion is set one layer at a time. With nothing selected: **Animations**, then Figma's help card "Adding motion to layers" ("Select a layer on the page, then use Add CSS animation to give it new motion.") with a close that keeps it closed in this browser (`finetune:tip:motion`).
  - **Playback speed for debugging only** (under the kind line, while an animation is selected; its label reads as the kind line's name does; each cell's tooltip reads "Test in 0.25×" and so on): 0.25×, 0.5×, 1× and 1.5×, Alignment's segmented cells spread across the row. A debugging aid for watching motion slower (or faster): the selected animation's layers play at that speed (CSS and JavaScript, one replayed or started later included) while the rest of the page stays at 1×. It's never an edit: nothing is saved or copied, and leaving Motion or the selection puts them back to 1× (only the animations it changed).
  - **Groups, read from the code**: layers that run the same animations (the same `animation-name` list, or a JavaScript call's same keyframes, as "the intro rises in" over three lines or a staggered menu) are one group: outlined, picked, listed and tuned as one. Its kind line reads "Group", how many layers and the animation (`3 layers · hl-rise`). A layer with an animation of its own is a group of one, shown as that layer.
  - **Picking in Motion**: hover and a click find the nearest layer with motion under the pointer (a CSS `animation`, or a JavaScript animation finetune has seen) and take its whole group; anything else is picked as in Design (the outermost layer below the level she's in, a ⌘G group as one), so an animation can be added to it. A click on nothing clears the selection. A press only selects: moving, the marquee, resizing, grouping and text editing are Design's. Switching to Motion turns a selection with motion into its whole group, and keeps any other. The selection has no size label in Motion (the size is Design's). Every group on screen is outlined (pink at 50%, one box around all its layers), each box following its layers as they move; the groups are read again every second.
  - **Motion's accent** is UI3's pink (pink-500: `#FF24BD`, `#F316B0` in dark) where Design uses its blue: the selection, hover and size label, field focus, the bar's chosen cell, the picked row, a menu's highlighted item and the curve (`html.ft-motion` is set while Motion shows). Every popover and menu closes when the tab changes.
  - **Adding an animation**: a layer (or group) with none shows one full-width button, **Add CSS animation** (Figma's secondary button), which opens the list to pick from (only a layer without one gets it; one that has animations tunes those): the page's own `@keyframes` first, under "Your tokens", then, under a line, Figma's generic ones under "Presets" (Dissolve, Move in, Move out, Push, Slide in, Slide out; Instant and Smart animate have no CSS of their own). Each generic one fades or moves up; Direction and Distance turn it afterwards. Picking one adds it to every layer (a group's all at once, so it moves as one unit) with Figma's default timing, ease out over 300ms, filling both ends; each layer's `animation-*` lists get one more entry. A generic one becomes a new `@keyframes` on the page, named for it (`slide-in`, or `slide-in-2` when taken), kept in finetune's own stylesheet (`#finetune-keyframes`) and in the edits, so Save, undo and Reset carry it; Copy lists it whole as `@keyframes slide-in (new)`, her later changes to it included.
  - **Animation** (when the layer has a CSS `animation` or a JavaScript one): Play / Pause and Replay in its header (they drive the page's animation; they aren't edits). Replay plays the animations again from the start (a group's together, so its stagger plays), a one-shot that already finished included (its `animation-name` is switched off and back on, which isn't an edit); Play resumes a paused one or replays a finished one, and the icon follows the animation as it starts and ends. Every edit in its settings replays the layers too, so a one-shot that already ran shows the change (a burst, like a curve being dragged, replays once it settles), then one row per animation, as Figma lists a layer's interactions: its `@keyframes` name and duration (a JavaScript one: the properties it animates, or its `id`, and "JS · 400ms"). A row opens its settings in the panel, under it (one at a time; a click on the row closes them; with one animation they start open), laid out as Figma's Interaction popover, label on the left, in groups split by a line. The layers on the page are the preview: every edit replays them.
    - **Keyframes**: which `@keyframes` play, from the same list as adding one (the page's own, then the generic ones; a JavaScript animation's are in its call, so this is a label). Then only what applies, read from the keyframes (a fade has no direction; a roll left has one): **Direction** (Left, Right, Down, Up; which way it moves, from its first keyframe to its last, or out to its farthest and back) and **Distance** (how far, in its unit) when it moves; **Scale** when it scales; **Rotation** when it turns; **Opacity** when it fades. Each reads the keyframe farthest from rest (scale 1, no turn, opacity 1); an edit changes that keyframe (every keyframe at that value). A direction turns every keyframe's move (flipped along its axis, swapped across it); a distance scales them all. Moves, scales and turns are read from the `translate`, `scale` and `rotate` properties or the `transform`'s functions, and written back the same way; one set with a `var()`, a `calc()` or mixed units isn't offered.
    - For a group, every edit goes to all its layers, and a value they don't share reads Mixed. **Delay** is when the group starts (its first layer's delay; typing shifts them all) and **Stagger** the step from one layer to the next in the order they start (by delay, then by their order in the code; typing spaces them evenly; Mixed when the code's steps aren't even).
    - **Easing** (the curve in front of its name; Figma's presets: Linear, Ease, Ease in, Ease out, Ease in and out, Ease in back `cubic-bezier(0.3, -0.05, 0.7, -0.5)`, Ease out back `cubic-bezier(0.45, 1.45, 0.8, 1)`, Ease in and out back `cubic-bezier(0.7, -0.4, 0.4, 1.4)`; and **Custom bezier**, which shows the curve editor: two handles to drag, x from 0 to 1, y from -0.5 to 1.5), **Duration** and **Delay** in ms.
    - **Iterations** (a number, or ∞), **Playback** (CSS's `animation-direction`: Normal, Reverse, Alternate, Alternate reverse) and **Fill mode** (None, Forwards, Backwards, Both).
    - **JavaScript animations** (`element.animate()`): finetune wraps `animate()`, so it sees every call made after it loads (one running from before is found through `getAnimations()`). An animation is known by its keyframes as the call gives them (or its `id`). Edits go on its running copies and on every later call, so they survive the page running it again: timing (a group layer's delay is its own), and keyframe values by index. Copy lists it as `animate() <properties>`, the layers it runs on, the function that calls it when the browser names one, and each change as was → now. Replay plays its copies again (a page's `onfinish` handler runs again too).
    - Timing edits are the layer's `animation-*` longhands, one value per animation in `animation-name` order (`animation-duration: 1000ms, 1s`); a running animation takes them without restarting. What the keyframes do is written into the page's own `@keyframes` (live, in its stylesheet), so every layer using them follows, as the code would; Save, Copy and undo carry them like any edit.
  - **Animations** (nothing selected): one row per group on the page, leading with what's animating (its layers by class: the class its group's layers don't all share, so three lines read apart; or id, or tag), then the animation it runs; a click selects the group. None: "No animations running on this page."
  - **Not started yet** (under it, when there are any): CSS animations the page's stylesheets give layers that aren't running them, because the rule needs a class the page adds later (on scroll, on a click). A rule counts when its selector, less one of its classes, matches layers on this page; that class is what starts it, on the layers that hold it in the selector. Each row has **Play**, which adds that class where the page would and selects what it animates, ready to tune. That's the page's own state from then on (a reload puts it back), not an edit. Rules for other pages, or started by a hover or an attribute, aren't listed.
  - A layer with a transition animates Design edits too, as the code would. Dragging and resizing don't wait for it (the layer has `data-ft-still` while it moves), and the selection follows a layer that moves on its own, the panel's numbers catching up when it lands.
- **Nothing saves on its own.** Edits show live but stay in memory until Save puts them in localStorage (per page, `finetune:edits:<path>`). A reload before Save drops them. Reset forgets the saved ones and reloads the page as written; then a toast over the bottom bar says "Your edits were reset to what's in the code" with **Undo** for 10 seconds before it fades. Undo brings back what showed before Reset, as it was: what Save had stored goes back in storage, and unsaved edits come back unsaved (one more reload, then "Your edits are back"). With nothing to reset (no edit on the page and nothing Save stored), Reset is greyed out, as Undo and Redo are with nothing to step to. (`finetune.reset()` called then says "No edits to reset: the page already matches the code") While Reset's toast shows, Undo in the panel's top row and ⌘Z undo the Reset too. Every action that can be undone says so in a toast with **Undo** (and a close ×) that stays 10 seconds before it fades: Save (Undo puts back what the browser had stored before; the edits on the page stay), Reset, ⌘G and ⇧⌘G, Align all items (Undo is ⌘Z's), Save as style and deleting a style (Undo removes or restores it). Toasts that can't be undone (Copy changes, notices) stay 1.8 seconds. Toasts sit above the Design / Motion bar.
- **Figma's shortcuts**, wherever finetune does the same thing, each shown in its button's tooltip (Mac's symbols on a Mac, Ctrl, Alt and Shift elsewhere): ⌘Z and ⇧⌘Z undo and redo; ⌘G and ⇧⌘G group and ungroup; ⌘\\ Hide UI; ⌥8 and ⌥9 Design and Motion; ⌥⌘S Save; ⇧⌘E Copy changes (Figma's Export key: ⇧⌘C is Chrome's Inspect element, ⌘S its Save Page As, so neither is taken over). In Design, with a layer or a selection: ⌥A, ⌥H and ⌥D align left, horizontal centers and right; ⌥W, ⌥V and ⌥S top, vertical centers and bottom; ⇧H and ⇧V flip; ⇧⌘H shows or hides; 1 to 9 and 0 set the opacity, 10% to 100%; the arrow keys nudge 1px, 10px with Shift. ⌃G (Ctrl+Shift+4 elsewhere) shows or hides the layout grid, Figma's Show layout grids (on a Mac ⌘G alone groups, so ⌃G is free): turned on with nothing selected, the panel shows the Horizontal layout (brought back if hidden, in Design if Motion was showing), with a layer selected it stays as it is, and with no layout yet it adds the usual 12 columns; the grid's eye shows the key. finetune's own (Figma has none): ⌥⌘T flips the theme. None fires while typing in a field or in words being edited.
- **Undo and redo** sit at the left of the panel's top row, before Reset (also ⌘Z and ⌘⇧Z, Ctrl on Windows; a field or text being typed in keeps its own). Each change is one step once it settles, so a drag, a color scrub or a burst of typing undoes as one; hover previews never count. Undoing past the first edit puts back exactly what the page had. Steps last for the visit; Save keeps the result, not the history.
- **Copy changes** copies the list the bake reads (below). It copies what's on screen, saved or not.
- **Page** (nothing selected, or a click on the page itself): the page fill, plus **Horizontal layout** (Figma's layout guide, as columns): one layout at a time. It starts as **the page's own grid** when the code has one: the widest CSS grid with four or more equal columns, at least half the window wide, read as count, gutter (`column-gap`) and margins (equal margins are Stretch, otherwise Left with an offset). That's the default; every field can be tweaked, and Styles keeps it at the top under "From the page" to go back to. A layout she saved for the page wins over it. With neither, it shows a warning, "Layout not defined.", and **Add layout** (the usual 12 stretched columns, 40 margin, 20 gutter, in red at 10%). Its row reads "Columns (12)": the swatch shows its color and opens the color settings, the eye shows or hides it. Under the row sit its fields: Count (one column, alone on its row), Type (Stretch, or packed Left / Center / Right), Width (Auto when stretched), Margin (stretched) or Offset (packed), and Gutter; typing redraws the columns on every keystroke (Escape puts the old value back). The header's **Save as style** (bookmark) asks, in place, **Apply to all pages** or **Just this page**, and saves the layout named from its numbers ("12 col · 20 gutter · 50 margin"; the same numbers aren't saved twice). **Styles** (four circles) opens **Active layout guides**, a popover left of the panel as Figma's Layout guide styles is (a close at the right of its title, no search): the page's own grid under "From the page", then hers under "This page" and "All pages" (or "No saved styles yet"), each row a columns icon and its name. Hovering a row shows it on the page, a click applies it and closes the popover, leaving the list puts hers back, and a saved row's trash can (on hover, where Figma's Edit style sits) deletes it, with Undo. Toasts about styles don't name the layout ("Saved style", "Already saved", "Deleted style"). Styles are kept in the browser the moment they're saved (`finetune:styles` for every page, `finetune:styles:<path>` for one), not with Save. Under the fields sits **Align items to nearest column**: left, horizontally and right. Each button is an action that springs back: it moves every item on the page (what she could select, outermost only), snapping its edge to the nearest column edge, or for horizontally putting it in the middle of the page, then toasts "Align all items left" (or right, horizontally). Those moves are ordinary edits (`translate`), so Copy and the bake carry them. The layout itself is saved with Save but never copied: it's for placing things, not a change to bake.
- **The page itself is the canvas.** The body, or a wrapper that paints the whole window (an app's `<main>`), is never selected; clicking it shows Page, and the Page fill paints it.
- **Fonts preview on hover**: the selected text wears each family the pointer passes over in the font menu. Leaving the menu or pressing Escape puts it back; only a click changes it.
- **Appearance**, as in Figma. **Opacity** and **Corner radius** are a field with a slider under it (drag or click anywhere on it; the field takes typing and arrow keys); the eye beside Opacity hides the layer. Corner radius runs from 0 to half the layer's short side and writes `border-radius`. **Independent corners** (its toggle) opens four fields, top left, top right, bottom left, bottom right, written as the `border-*-radius` longhands; the main field then reads Mixed when they differ. **Corner smoothing** (the sliders icon beside it) opens a popover with Figma's smoothing, 0 to 100% with a mark at 60% (iOS): it writes CSS `corner-shape: superellipse(k)` with each radius scaled to match Figma's curve (60% is radius × 1.195 and superellipse(1.32); 0 takes `corner-shape` off), while the fields keep showing Figma's radius. **Blend mode** is a dropdown row (Figma's list), written as `mix-blend-mode`. The Adjustments icon sits in the header.
- **Stroke and Effects** (any layer but text, her call), as in Figma, after Fill. **Stroke**: + adds one (black, Inside, 1); its row has the color, opacity, eye and remove, then Position (Inside, Center, Outside) and Weight. It's written as an `outline` (Inside and Center by a negative `outline-offset`), so it never moves the layout; the page's own outline shows as its stroke, a CSS border doesn't. **Effects**: + adds a drop shadow at the top (0 4, blur 4, black at 25%); each row has the sun (its settings: X and Y, Blur, Spread and Color for a shadow, Blur for a blur), the type (Inner shadow, Drop shadow, Layer blur, Background blur), remove and the eye. The page's own shadows and blurs show as effects. Removing one the page had writes `none`, so it stays removed. **Adjustments** (the sliders icon in Appearance, on any layer but text) are an image's seven sliders: on a box they apply to the whole element, in the same `filter`; on an image the icon opens its image popover, where Figma keeps them. An image's Fill thumbnail opens its image popover: the fit (Fill, Fit, Crop, Stretch: `object-fit`), the preview with a **Replace image** button over it (picks a file from her computer; it shows at once, Save keeps it in the browser's storage, which holds about 5MB, and Copy lists it as `src: new image "name"`), and the seven sliders.
- **Position, as in Figma:** Alignment, X and Y, and Rotation with Rotate 90° right and the two flips. For one layer, Alignment lines it up inside its parent, the parent's box inside its border and padding, as Figma lines a layer up in its frame. Each click is one undo step, and the moves are ordinary `translate` edits.
- **Groups are the code's containers, 1:1** (her rule: true to code over Figma). A click picks the outermost layer under the pointer below the level she's in: the page, until she double-clicks into a group. Wrappers that only hold the page (window-sized, or `display: contents`) are passed through, as Figma passes through a top-level frame. Double-click goes one level in (then, on words, edits them); **⌘-click** (Ctrl) picks the deepest layer; Escape steps back out a level. The hover outline shows what a click would pick. A single layer's panel opens with its **kind**, read from the code (Group: it holds other elements; Text; Image; Vector; SVG; Box), and its element (`nav.hl-links`); a Group also shows how many items it holds on the right, in the kind's own type in the lighter text color (`4 items`). Figma's tools on that line are left out. A ⌘G group reads just "Group" (with its item count) and several layers "N selected": neither is an element in the code yet, so there's no name (the bake wraps a group's layers in a new element). Their section below is Position, as in Figma.
- **Components, as Figma's instances.** A layer is a component when a component in the code renders it as its one outermost element (a React component's single root, from React's development build, the outermost one written in the page's code rather than in node_modules: an icon library's `Envelope`, not its inner `IconBase`), or when it's a custom element. In Design, its hover and selection outlines, corners and size label are Figma's component purple (`#9747FF`), and its name sits over its top left with the component mark. Its panel opens with the component's name, then a note, "Editing every DemoButton." (its name), and **Override** (an instance mark, Figma's secondary button across the width). Until it's overridden, an edit to its look reaches every instance of it on the page at once and is recorded once, for the component; a move, a turn or a flip, and its words, are always this instance's own. Override (pressed, purple at 12%, the note then reads "Editing only this DemoButton.") makes this instance's edits its own, over the component's for those properties; pressed again, edits reach every instance again (its own stay). Override is saved with Save and undone with ⌘Z like an edit. Motion is unchanged: its accent, and its edits one layer at a time.
- **Clip content** (Figma's checkbox, the last line of Layout, after Spacing, on any layer that holds other elements; checked, it shows a heavier tick, and hovering it fills the box): the container's `overflow`, checked when it isn't `visible` (the code's `hidden`, `clip`, `auto` or `scroll`). Checking writes `overflow: hidden`, unchecking `overflow: visible`; landing back on what the code says takes the edit off. A ⌘G group has none: it isn't one element in the code until the bake wraps it. Flow's icons are drawn after Figma's (small squares scattered, stacked with a down arrow, side by side over a right arrow, two by two), at the 16px they show at so every edge lands on a whole pixel.
- **A group's Layout** adds **Flow** (Freeform, Vertical, Horizontal; Grid shows only on a CSS grid, which isn't made here), written as `display: flex` + `flex-direction`, or no flex for Freeform, and **Spacing**: the `gap` on a flex or grid (`row-gap` for Vertical, `column-gap` for Horizontal; a grid shows its two side by side on one line, across then down, as `column-gap` and `row-gap`; Figma's grid size picker and auto layout's Resizing, Alignment and Padding aren't here), or, when the children sit in one column or row on anything else, a move of each child after the first so every gap is the value (the ones below move down too). A ⌘G group gets the same Spacing between its layers.
- **Resizing, as in Figma:** drag a corner of the selected layer. The opposite corner stays put, Shift keeps the proportions (an image always keeps them), and the drag is one undo step. It's written as `width` / `height` (the CSS size for that outer size, padding and border counted), or a vector's own geometry. Only one layer that isn't rotated shows the corners (the rest would be finicky).
- **Vectors** (SVG shapes: path, rect, circle, ellipse, line, polyline, polygon, g, use) are objects with what SVG can do. A click picks the outer `<svg>` (kind SVG, handled like a box); double-click goes in. Moves are `translate` in the SVG's own units (a viewBox can scale them), so a 50px drag moves 50px on screen. Rotate and flip set `transform-box: fill-box` + `transform-origin: center` so the shape turns in place. Size: a rect's `width` / `height`, a circle's `r`, an ellipse's `rx` / `ry`, anything else `scale` with `vector-effect: non-scaling-stroke` so its stroke keeps its weight; the top-left stays put. Corner radius only on a rect (`rx` / `ry`). **Fill** is the SVG `fill` (+ adds Figma's D9D9D9; a gradient or pattern from the code shows but isn't edited); **Stroke** is `stroke` + `stroke-width`, always Center (SVG draws it centered); **Effects** are only Drop shadow and Layer blur, as `filter: drop-shadow()` (half Figma's blur: drop-shadow's reaches twice as far) and `blur()`. Words inside an SVG are text: their color is `fill`, their alignment `text-anchor`, and they have no box to size. **Icons**: an `<svg>` whose shapes paint with `currentColor` (Phosphor's, Lucide's) shows its color as its **Fill** (the svg's CSS `color`), a line icon's **Stroke** as just its **Weight** (`stroke-width` on the svg, in the icon's own units: Lucide's 2), and no Corner radius or box stroke. Any `<svg>`'s **Effects** are Drop shadow and Layer blur as `filter`s, so a shadow follows the drawing, not its box. An icon's weight or which icon it is are props in the code (Phosphor's `weight`), not CSS, so the panel doesn't change them.
- **Dragging moves, as in Figma.** Press on a layer and drag: it's selected and follows the pointer, and so does the rest of the selection when she presses inside one (a group moves as one; a layer inside another selected layer rides along with it). Each layer's move is a `translate`, so it's an ordinary edit: the Position fields follow it live, the whole drag is one undo step, and Copy and the bake carry it. A press inside a bigger selection that ends without a drag narrows the selection to what she clicked. Shift-click never drags.
- **Groups, as in Figma.** Shift-click adds a layer to the selection or takes it out. A drag that starts on the page draws a marquee and selects every layer it touches, live (a group as one); shift-drag adds to the selection, and a click without a drag clears it. **⌘G** (Ctrl+G) groups the selection; **⌘⇧G** ungroups it and leaves its layers selected. A click on any layer in a group selects the whole group (the hover outlines it as one); double-click goes into the group and selects that layer, double-click again edits its text, and Escape steps back out a level. Two or more selected show "Group" or "N selected" with **Alignment** (Figma's six: Align left, horizontal centers, right, top, vertical centers, bottom; each lines the layers up on an edge or the middle of the selection's box, a selected group moves as one, and a selection that is just one group lines up its own layers; each click is one undo step, and the moves are ordinary `translate` edits) and X and Y, which move them all together, and Align items to nearest column moves a group as one. The live page is never rewrapped (that breaks a React page): a group is how layers select and move here, saved with Save, and Copy lists it as `group N  a, b, c` for the bake to wrap in a real layer.
- **Inline text** (a span) ignores move, rotate, flip and size, so the first of those edits also sets `display: inline-block` on it. That's in the changes list too.
- **Fields only commit a typed change.** Clicking into a field and out again records nothing.

## Controls

Every control takes `type`, `value` and `label` (default: its key).

### range

A slider plus a number field you can type in.

| option | default |
| --- | --- |
| `value` | `min` |
| `min` | `0` |
| `max` | `100` |
| `step` | `1` |
| `unit` | `""` |

Writes `value + unit`. No unit means a bare number, which is right for unitless line-height and for values used inside `calc()`. The number field accepts values past `min` and `max`; the slider stops at them.

### select

A button grid, never a dropdown.

| option | default |
| --- | --- |
| `value` | the first option |
| `options` | `[]` |
| `cols` | `4` |

Options are plain values or `{ label, value }`, so a button can read "H1 36" while writing `h1`. Writes the chosen option's value.

### toggle

| option | default |
| --- | --- |
| `value` | `false` |
| `on` | `1` |
| `off` | `0` |

Writes `on` when true and `off` when false.

### color

Chips plus a hex field.

| option | default |
| --- | --- |
| `value` | `"#000000"` |
| `chips` | `[]` |

Hex only: `#rgb`, `#rgba`, `#rrggbb`, `#rrggbbaa`. The field takes a value with or without the `#`.

### text

| option | default |
| --- | --- |
| `value` | `""` |

For copy. Give it a key without `--` and apply it in `onChange`.

## Copy formats

**Copy JSON** is the values object. Raw values: numbers stay numbers, toggles stay `true` or `false`, no units. `onChange`-only keys are included.

```json
{
  "--hero-size": 40.6,
  "--hero-weight": 400,
  "--hero-leading": 1.12,
  "--hero-tracking": -0.02,
  "--hero-ink": "#F6F4EF",
  "--hero-italic": false,
  "eyebrow": "Meta · Redesign",
  "speed": 1
}
```

**Copy CSS** is a block for the `target` selector, `--` keys only, written exactly as the panel writes them: units added, toggles as their `on` or `off`.

```css
:root {
  --hero-size: 40.6px;
  --hero-weight: 400;
  --hero-leading: 1.12;
  --hero-tracking: -0.02em;
  --hero-ink: #F6F4EF;
  --hero-italic: normal;
}
```

If the browser blocks the clipboard, the panel shows the text in a box to copy by hand.

## What the panel remembers

The last values per `id`, in localStorage under `finetune:<id>`. On load, a stored key that no longer matches a control is dropped, and a stored value that no longer fits its control falls back to the schema. **Reset** returns every control to its `value`. finetune never writes to disk.

## Bake checklist

1. Get the tuner's Copy JSON.
2. Find the `finetune()` call with that `id`.
3. For each key, find where the committed value lives: the custom property's declaration in the stylesheet (usually `:root`), or the config value. For a key without `--`, wherever that value is used (markup, config, a script constant).
4. Write the new value in that file's format. `range`: add the control's `unit`. `toggle`: write `on` or `off`. Skip values that already match.
5. A key with no committed home: don't invent one. List it and ask.
6. Remove the `finetune()` call, any code that only fed it, and the script tag that loads `finetune.js` unless another `finetune()` call on the page still uses it.
7. List every file and line touched.
8. Ask before committing.
